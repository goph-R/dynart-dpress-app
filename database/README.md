# Development database

Before 1.0 there are **no rename migrations**. When the entities change, the database is thrown
away and rebuilt from the example data rather than migrated in place.

## Resetting

```bash
database/reset.sh          # Linux, macOS, Git Bash
database\reset.bat         # Windows
```

That drops the database, runs `dpress install`, runs `seed.php`, and rewrites
`example-data.sql` from the result. On Git Bash for XAMPP the mysql binaries are not on the
path, so:

```bash
MYSQL=/c/xampp/mysql/bin/mysql MYSQLDUMP=/c/xampp/mysql/bin/mysqldump database/reset.sh
```

## Loading the example data without rebuilding

```bash
mysql -u root dpress_dev < database/example-data.sql
```

The dump carries the schema as well, so this works against an empty database.

## The files

| File | What it is |
|---|---|
| `seed.php` | Creates the example data **through the services**, so the events fire and the audit trail looks like a real site's. This is the thing to edit. |
| `example-data.sql` | A dump of the result. Regenerated by `reset.sh`; do not hand-edit it. |
| `reset.sh` / `reset.bat` | Drop, install, seed, dump. |

## Content

Four posts and two pages, including a draft (visitors get a 404, an editor can preview it), a
post with no lead separator, one with accents in the title to show the slug folding, and a page
with a child. `welcome-to-dpress` has a second revision by the editor, so `content:history` has
something to show.
